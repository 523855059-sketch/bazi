# 解读代理部署

让访客**不用自备 Key** 也能生成解读：Key 藏在一层转发服务里，网页源码看不到它。

不部署这套东西也能用——那时每个人在页面上填自己的 Key 直连 DeepSeek，费用各付各的。两套并存，谁填了 Key 就走谁自己的额度。

---

## 一、它怎么工作

```
访客浏览器 ──► Worker（Cloudflare） ──► api.deepseek.com
                  ▲
                  └── 你的 Key 存在这里的环境变量里
```

网页里只有一个 Worker 地址，没有 Key。访客点「生成解读」，请求先到 Worker，Worker 补上 Key 再转给 DeepSeek，结果原样流回浏览器。

代码在 `deploy/worker.js`，前端开关在 `lib/config.js`。

---

## 二、准备

- 一个 Cloudflare 账号（免费注册，Workers 免费额度对个人和小圈子够用，具体限额以官网为准）
- 你的 DeepSeek API Key（platform.deepseek.com）

---

## 三、部署 Worker

1. 登录 <https://dash.cloudflare.com>，左侧找 **Workers & Pages**（新版可能叫 **Compute (Workers)**）
2. **Create** → 选 **Worker** → 给它起个名字，例如 `bazi-proxy` → **Deploy**
3. 进入刚建的 Worker，点 **Edit code**（或 Quick edit）
4. 把编辑框里的示例代码全删掉，粘贴 `deploy/worker.js` 的全文 → **Deploy**
5. 记下它给出的地址，形如 `https://bazi-proxy.你的子域.workers.dev`

Cloudflare 界面改版比较频繁，认准这条路：**新建 Worker → 粘贴代码 → Deploy**，按钮名字变了也绕不开这三步。

## 四、配置密钥与口令

在这个 Worker 的 **Settings → Variables and Secrets**（旧版叫 **Environment variables**）：

| 变量名 | 必填 | 值 |
|---|---|---|
| `DEEPSEEK_KEY` | 是 | 你的 DeepSeek Key。有 Encrypt / Secret 选项就勾上 |
| `ACCESS_CODE` | 建议 | 自己定一个口令，例如 `bazi-2026-x7` |
| `ALLOW_ORIGIN` | 建议 | `https://523855059-sketch.github.io`（**只填域名，不带 `/bazi` 路径**） |

改完要 **Deploy** 一次才生效。

## 五、把地址填进前端

编辑 `lib/config.js`：

```js
window.BZ.config = {
  proxyUrl: 'https://bazi-proxy.你的子域.workers.dev',
  proxyCode: 'bazi-2026-x7'      // 与 Worker 里的 ACCESS_CODE 一致
};
```

推送到 GitHub（`git add -A && git commit -m "开启解读代理" && git push`），约 1 分钟后生效。

`sw.js` 的缓存版本号已随本次改动升到 `bazi-v4`，老访客会自动换到新文件。

## 六、验证

开一个**无痕窗口**打开 https://523855059-sketch.github.io/bazi/ ，排一次盘：

- 「AI 解读」标题应显示 **本站已开通**
- Key 输入框的占位文字是「（可选）自己的 Key，留空用本站服务」
- 不填 Key 直接点「生成解读」，应当流出文字

任一项不对，先看下一节。

## 七、安全边界（必读）

这套东西降低的是**滥用的门槛**，不是绝对防护。三件事要清楚：

1. **口令在前端是明文**。`lib/config.js` 会随网页公开，懂技术的人 F12 就能拿到口令。它的作用是挡住随手扫描到的脚本，挡不住存心的人。
2. **`ALLOW_ORIGIN` 也能绕过**。它限制的是浏览器发起的跨域请求，命令行工具伪造一个 Origin 头就过去了。
3. **真正的兜底是账户余额**。去 DeepSeek 平台看一下有没有充值/额度上限设置，把能烧掉的钱锁死。这是唯一确定有效的止损。

想更严一点，可以加 Cloudflare 的 Rate Limiting（按 IP 限速），或把 Worker 绑到自己的域名上再加访问策略——按需再说，多数小圈子用不上。

---

## 八、出问题怎么查

| 现象 | 原因 |
|---|---|
| 标题没变成「本站已开通」 | `lib/config.js` 没填 `proxyUrl`，或推送后还没重新构建 |
| 报「请求被拒绝（403）」 | 口令对不上，或 `ALLOW_ORIGIN` 填错了（注意不要带路径） |
| 报「Worker 未配置 DEEPSEEK_KEY」 | 环境变量没加或没点 Deploy |
| 报「上游连接失败」 | Cloudflare 到 DeepSeek 的网络问题，重试 |
| 国内打开很慢 | `workers.dev` 域名在国内时快时慢；想稳就绑自己的域名（Cloudflare 免费套餐支持自定义域） |
| 想临时关掉代理 | 把 `lib/config.js` 的 `proxyUrl` 清空再推送，页面立刻回到「各填各的 Key」 |
